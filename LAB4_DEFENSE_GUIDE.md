# ЛР4: как устроен календарь

## Короткое объяснение работы

«Я сделал сетку месяца самостоятельно: вычисляю количество дней и день недели первого числа.
Пустыми ячейками сдвигаю первое число под нужный день недели. При нажатии на дату меняю
`selectedDate` через `setState` и показываю события этого дня. События хранит отдельный
`EventRepository`. Форма возвращает новое или изменённое событие на экран календаря.
Из дополнительных заданий выбраны цвета категорий. Ещё есть отметки занятых дней и кнопка “Сегодня”».

Это описание реализации. Перед защитой стоит самостоятельно пройти код и попробовать изменения ниже.

## Что находится в файлах

### `lib/main.dart`

`main()` запускает Flutter через `runApp`. `CalendarApp` — `StatelessWidget`: у него нет своих
меняющихся данных. Он создаёт `MaterialApp`, задаёт тему и открывает `CalendarScreen`.

### `lib/models/calendar_event.dart`

`CalendarEvent` — обычный класс, который объединяет данные одного события.

| Поле | Что хранит |
| --- | --- |
| `id` | Номер события; позволяет найти его при редактировании, даже если названия одинаковые |
| `title` | Название |
| `start` | Дату и время начала в одном `DateTime` |
| `end` | Окончание или `null`, если пользователь его не указал |
| `category` | Строку «Учёба», «Работа» или «Личное» |

`required` означает, что аргумент надо передать при создании объекта.
`DateTime?` допускает отсутствие значения. `id = 0` — начальное значение для нового события,
пока репозиторий не присвоил ему номер. Поля не относятся к виджетам: это просто данные.

### `lib/repositories/event_repository.dart`

`_events` — основной список. Подчёркивание делает имя доступным только внутри этой Dart-библиотеки.
`nextId` — следующий свободный номер, изначально 1.

- `addEvent` присваивает номер, увеличивает счётчик и добавляет объект в список.
- `updateEvent` находит элемент по `id` обычным циклом и заменяет его.
- `deleteEvent` удаляет переданный объект из списка.
- `getEventsForDay` собирает события указанного дня в отдельный список и сортирует его по началу.

Отдельный список нужен, чтобы вернуть только события выбранной даты и расположить их по времени,
не меняя порядок основного списка. Это новый список ссылок на те же объекты, а не глубокие копии событий.
Сортировка использует `compareTo`: более раннее время идёт первым.

`final` у списка запрещает присвоить переменной другой список. Добавлять и удалять элементы внутри него можно.
Базы данных, LocalStorage и записи в файл здесь нет. После полного перезапуска создаётся новый пустой репозиторий.

### `lib/calendar_dates.dart`

Здесь обычные функции без виджетов. Их используют оба экрана и репозиторий.

`daysInMonth(year, month)` возвращает `DateTime(year, month + 1, 0).day`.
Нулевой день следующего месяца — последний день текущего. Например,
`DateTime(2024, 3, 0)` — 29 февраля 2024 года. Високосность уже учитывает `DateTime`.

`firstDayOffset` получает `weekday` первого числа и вычитает 1.
В Dart понедельник имеет номер 1, воскресенье — 7. Для сетки нужны значения от 0 до 6.

`sameDay` сравнивает год, месяц и день. Часы и минуты не сравниваются:
события в 09:00 и 18:00 могут относиться к одной дате.

`formatDate` и `formatTime` собирают понятные строки. `padLeft(2, '0')` превращает `9` в `09`.

`parseDate` разбивает строку по точкам и проверяет формат `ДД.ММ.ГГГГ`, числа, диапазон месяца,
дни конкретного месяца и год от 1 до 9999. `int.tryParse` возвращает число или `null` вместо ошибки.
Проверка существования даты нужна до создания `DateTime`: сам конструктор может перенести лишние дни
в следующий месяц. Например, 31 февраля нельзя молча превращать в март.

`parseTime` разбивает строку по двоеточию, проверяет `ЧЧ:ММ`, часы 0–23 и минуты 0–59.
Результат — количество минут с начала суток: `09:30` превращается в `9 * 60 + 30 = 570`.
Так начало и окончание удобно сравнить обычным `<=`.

### `lib/pages/calendar_screen.dart`

`CalendarScreen` — `StatefulWidget`. Он создаёт объект `CalendarState`, где находятся меняющиеся данные.
Это обычный `State`, отдельная библиотека для управления состоянием не используется.

Основные поля:

- `repository` хранит события.
- `selectedDate` хранит выбранный день: по нему выделяется ячейка и получается список событий.
- `currentMonth` хранит первое число показываемого месяца.
- `monthNames` и `weekDays` содержат русские подписи.

Месяц и выбранная дата — разные понятия. Например, показывается октябрь, а выбран день 20 октября.
При переключении месяца выбранная дата сохраняется; другое число выбирается нажатием на него.
`DateTime` сам обрабатывает переход декабря в январь.
`selectToday` возвращает и выбранную дату, и показываемый месяц к сегодняшним значениям.

#### Как строится сетка

В `buildCalendar` считаются:

```dart
final offset = firstDayOffset(currentMonth.year, currentMonth.month);
final count = daysInMonth(currentMonth.year, currentMonth.month);
final cellCount = ((offset + count + 6) ~/ 7) * 7;
```

`offset` — количество пустых ячеек перед первым числом. `count` — число дней.
`cellCount` округляет общее количество ячеек вверх до полной недели.
Оператор `~/` — целочисленное деление. Прибавление 6 позволяет округлить вверх при делении на 7.
Например, 6 пустых ячеек + 31 день = 37; `(37 + 6) ~/ 7 * 7 = 42`, то есть 6 недель.

`GridView.builder` получает 7 колонок. Для ячейки с индексом `index` число вычисляется так:

```dart
final day = index - offset + 1;
```

Если оно меньше 1 или больше числа дней месяца, возвращается пустой `SizedBox`.
Иначе создаётся кнопка с числом. `return` здесь возвращает **виджет, который надо нарисовать**,
а не запускает обработчик нажатия. Нажатие произойдёт позже и вызовет `onPressed`.

Кнопка меняет `selectedDate` внутри `setState`. После этого Flutter снова вызывает `build`.
У выбранного дня синий фон, а у сегодняшней даты синяя обводка. Сегодняшний день берётся из `DateTime.now()`.
Если на дату есть события, под числом рисуется точка.
`FittedBox` уменьшает слишком крупное число до доступной ширины, чтобы оно не переносилось.

Внешний `ListView` прокручивает весь экран. Внутренняя сетка имеет `shrinkWrap: true`, чтобы занимать
высоту своих строк; её отдельная прокрутка выключена через `NeverScrollableScrollPhysics`.
`Expanded` в строке заголовка отдаёт названию месяца место между стрелками, а в строке дней недели делит ширину поровну.

#### События и категории

В `build` репозиторий возвращает события выбранного дня. Цикл `for` добавляет карточку для каждого события.
Если список пуст, показывается сообщение. Длинное название ограничено одной строкой с многоточием.

`categoryColor` через обычные `if` выбирает цвет значка карточки. Это и есть дополнительное задание
«Цвета категорий». Точки в календаре показывают только наличие событий; они не перечисляют все категории дня.
Нажатие на карточку открывает редактирование, а меню `⋮` содержит редактирование и удаление.
После удаления тоже вызывается `setState`, чтобы обновить список и точки.

### `lib/pages/event_form_page.dart`

Один экран используется для создания и редактирования. Если `event == null`, создаём новое событие.
Если объект передан — заполняем поля его значениями. `widget.selectedDate` и `widget.event` — входные данные экрана.

`TextEditingController` позволяет прочитать или установить текст поля. `initState` один раз заполняет поля,
а `dispose` освобождает контроллеры после закрытия экрана. В `build` заполнять их нельзя:
он вызывается повторно и мог бы стереть ввод пользователя.

`Form` объединяет поля. `GlobalKey<FormState>` позволяет вызвать у этой конкретной формы `validate()`.
Это назначение ключа отличается от `ObjectKey(todo)` в предыдущей лабораторной: там ключ связывал элемент списка с объектом.
Каждый `validator` возвращает текст ошибки или `null`, если всё хорошо.

`saveEvent` сначала проверяет форму. При ошибке делает `return` и ничего не сохраняет.
После успешной проверки создаёт `DateTime` начала и при необходимости окончания.
Из минут часы получаются через `~/ 60`, оставшиеся минуты — через `% 60`.
Знак `!` после результата разбора означает, что здесь ожидается значение, а не `null`:
эти же строки уже прошли валидаторы. Применять `!` без проверки опасно.

Название обрезается по краям методом `trim`; строка из одних пробелов не сохраняется.
Окончание можно оставить пустым. Если оно заполнено, оно должно быть строго позже начала в тот же день.
Переход через полночь и многодневные события в этом варианте не реализованы; это указано рядом с полем.

Сохраняется новый объект события. Исходный объект не изменяется во время ввода, поэтому «Отмена» оставляет его прежним.
При редактировании новый объект получает старый `id`, и репозиторий заменяет нужный элемент.

`SingleChildScrollView` позволяет добраться до кнопок при появлении клавиатуры.
Список категорий сделан стандартным `DropdownButtonFormField`, без стороннего пакета.

## Как два экрана передают данные

1. `openForm` вызывает `Navigator.push` и передаёт форме выбранную дату и, при редактировании, событие.
2. `await` ждёт закрытия формы. Интерфейс при этом не блокируется.
3. «Сохранить» вызывает `Navigator.pop(context, result)` и возвращает объект.
4. «Отмена» или обычная кнопка назад возвращает `null`.
5. Если результата нет, календарь ничего не меняет. Иначе добавляет или обновляет событие внутри `setState`.

`Future<void>` обозначает асинхронную функцию без полезного возвращаемого значения.
После `await` проверяется `mounted`: экран мог быть закрыт, пока форма была открыта.
`context` здесь используется для стандартной навигации Flutter. Собственной системы работы через контекст нет.
После сохранения календарь переходит на дату результата — это позволяет сразу увидеть событие, если его дату изменили.

## Четыре вопроса из ТЗ

**Как представить событие в виде модели?** Обычным классом `CalendarEvent`: номер, название,
начало, необязательное окончание и категория. Один объект — одно событие.

**Как сравнивать даты?** Для принадлежности к одному дню сравниваю год, месяц и день через `sameDay`.
Для порядка событий сравниваю полный `start` через `compareTo`. Равенство моментов времени не означает просто «тот же день».

**Как передавать данные между экранами?** Вперёд — аргументами конструктора при `Navigator.push`.
Назад — результатом `Navigator.pop`, который получает ожидающий `await`.

**Какие проблемы возникают с часовыми поясами?** Один момент может приходиться на разные даты в разных поясах.
Поэтому при обмене данными обычно согласуют хранение UTC и перевод в местное время для отображения.
Здесь используются локальные `DateTime` устройства, без синхронизации и преобразований зон.
Переезды между поясами, неоднозначное время при переводе часов и сетевой календарь этот учебный вариант не решает.

## Ещё вопросы, которые стоит уметь объяснить

1. **Почему два вида виджетов?** `CalendarApp` не хранит изменяемые данные, а календарь и форма хранят.
2. **Зачем `setState`?** Сообщает Flutter, что данные изменились и нужно перестроить интерфейс.
3. **`setState` сохраняет на диск?** Нет, только запускает обновление интерфейса.
4. **Почему не готовый календарь?** По условию сетку надо построить самому; расчёты находятся в `buildCalendar`.
5. **Для чего `+ 1` у номера дня?** Индексы начинаются с нуля, числа месяца — с единицы.
6. **Почему `weekday - 1`?** Перевожу номера 1–7 в число пустых ячеек 0–6.
7. **Почему список событий не хранится прямо в форме?** Форме нужен ввод, репозиторию — общий список всех событий.
8. **Чем `null` отличается от пустой строки?** `null` — отсутствие значения, `''` — существующая строка без символов.
9. **Зачем проверка `trim().isEmpty`?** Она запрещает название, состоящее только из пробелов.
10. **Почему `tryParse`, а не `parse`?** Неправильный пользовательский ввод даёт `null`, который можно проверить.
11. **Как проверяется февраль?** Число допустимых дней берётся из `daysInMonth` для конкретного года.
12. **Почему не сравнить строки времени?** Число минут позволяет явно проверить диапазоны и порядок.
13. **Что если окончание равно началу?** Валидатор запрещает его: используется `end <= start`.
14. **Что если окончание пустое?** Поле модели `end` остаётся `null`; карточка показывает только начало.
15. **Почему одинаковые названия допустимы?** Событие определяется по `id`, а не по названию.
16. **Как работает отмена?** Форма не меняет исходный объект и не возвращает результат сохранения.
17. **Что будет после обновления страницы?** Память приложения очистится, список событий станет пустым.
18. **Какая библиотека отвечает за хранение?** Никакая: используется обычный Dart-список.
19. **Зачем `isNotEmpty` перед точкой?** Отметка нужна, только если на этот день есть хотя бы одно событие.
20. **Что делает `const`?** Позволяет создать неизменяемое значение заранее, когда аргументы известны.
21. **Что такое `builder`?** Функция, которая возвращает виджет; сетка вызывает её для своих ячеек.
22. **Что такое callback?** Функция, переданная виджету на будущее событие, например `onPressed` при нажатии.
23. **Почему `return Card(...)` не означает нажатие?** Это описание элемента интерфейса; нажатие обрабатывает `onTap`.
24. **Чем отличается `ListView` от `Column`?** Список умеет прокручиваться, обычная колонка сама по себе — нет.
